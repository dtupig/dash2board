Acesse github.com/new

Crítico: as três caixas de inicialização ficam DESMARCADAS. README, .gitignore e license já existem no seu projeto. Marcar qualquer uma cria um commit no remoto, e o primeiro push falha com “rejected — fetch first”.

2Registrar a chave SSH

Foto do perfil → Settings → SSH and GPG keys → New SSH key

github.com/settings/ssh/new
Add new SSH Key
Authentication Key ▾
Cole o conteúdo de ~/.ssh/id_ed25519.pub — o arquivo .pub, nunca o outro.
Add SSH key

Gere e copie a chave antes de abrir esta tela:

ssh-keygen -t ed25519 -C "daniel.tupinamba@elytronsecurity.com"
eval "$(ssh-agent -s)"
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
pbcopy < ~/.ssh/id_ed25519.pub          # chave no clipboard

# depois de salvar no GitHub, confirme:
ssh -T git@github.com                    # "Hi <usuário>! You've successfully authenticated"

3Publicar

No terminal do VSCode, na raiz do projeto

git remote add origin git@github.com:dtupig/dash2board.git
git push -u origin main --follow-tags

4Proteger o branch main

Repositório → Settings → Rules → Rulesets → New ruleset → New branch ruleset

github.com/dtupig/dash2board/settings/rules/new
● Active ▾
Include default branch
Restrict deletions
Block force pushes
Require a pull request before merging
Required approvals: 0  (1 quando houver segundo desenvolvedor)
Require status checks to pass
✓ flutter
✓ guardrails
Create

Trabalhando sozinho, deixe Required approvals: 0 — mas mantenha os status checks obrigatórios. É o que impede subir código com flutter analyze sujo.

5Conferir a CI

Repositório → aba Actions → primeiro workflow após o push

github.com/dtupig/dash2board/actions

O job rules em amarelo é esperado: os testes de security rules são o achado A-02 da auditoria e entram antes do prompt 12.
